    Infrastructure Architecture

    This document details the infrastructure setup, Docker configuration, networking, and deployment architecture.

    Docker Compose Architecture

    graph TB
    subgraph dockerHost [Docker Host]
        subgraph network [nolain-network Bridge]
            nginx[nginx:alpine<br/>Port 80:80, 443:443]
            frontend[nolain-ocr-frontend<br/>Port 80 internal]
            backend[nolain-ocr-backend<br/>Port 8000 internal]
            celery[nolain-ocr-celery-worker<br/>No external port]
            redis[redis:7-alpine<br/>Port 6379:6379]
        end

        subgraph volumes [Volumes]
            backendData[./backend/data]
            nginxConf[./nginx/nginx.conf]
            certbotConf[./certbot/conf]

    subgraph external [External Access]
        internet[Internet]

    internet -->|HTTP/HTTPS| nginx
    letsencrypt -->|ACME Challenge| nginx

    nginx -->|Proxy /| frontend
    nginx -->|Proxy /api| backend
    nginx -.->|Mount| nginxConf
    nginx -.->|Mount| certbotConf
    nginx -.->|Mount| certbotWww

    backend -->|Queue Tasks| redis
    backend -.->|Mount| backendData

    celery -->|Get Tasks| redis
    celery -.->|Mount| backendData

    frontend -->|Fetch Data| backend

    Service Definitions

    1. Backend Service

    Image: nolain-ocr-backend:latest

    Dockerfile:

    FROM python:3.11-slim
RUN apt-get update && apt-get install -y poppler-utils libgl1 libglib2.0-0
COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt
COPY backend/ ./backend/
RUN mkdir -p ./backend/data
EXPOSE 8000
CMD ["uvicorn", "backend.main:app", "--host", "0.0.0.0", "--port", "8000"]

    Key Features: - Python 3.11 base - Poppler-utils for PDF processing - Installs all Python dependencies - Creates data directory for uploads - Runs Uvicorn ASGI server

    Volumes: - ./backend/data:/app/backend/data - Persistent file storage

    Environment Variables: - Supabase credentials (SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY) - Mistral AI API key (MISTRAL_API_KEY, DEFAULT_AI_MODEL) - Stripe keys, price IDs, and top-up pack configuration - Subscription limits (per tier) - Celery/Redis URLs - Frontend URL, admin user ID

    Restart Policy: unless-stopped

    2. Frontend Service

    Image: nolain-ocr-frontend:latest

    Dockerfile:

    # Stage 1: Build
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
ARG VITE_SUPABASE_URL
ARG VITE_SUPABASE_ANON_KEY
# ... other VITE_ args
RUN npm run build

# Stage 2: Serve
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

    Key Features: - Multi-stage build (Node → Nginx) - Bakes environment variables at build time - Serves static files via Nginx - SPA routing configuration

    Build Arguments: (VITE_* variables) - Supabase URL and anon key - Google Client ID (Sheets export) - Stripe price IDs and display pricing - Page limits (all tiers)

    Restart Policy: unless-stopped

    3. Celery Worker Service

    Image: Reuses nolain-ocr-backend:latest

    Command Override:

    celery -A backend.core.celery_app.celery_app worker --loglevel=info

    Key Features: - Same image as backend - Different entry point (Celery instead of Uvicorn) - Shares data volume with backend - Same environment variables

    Dependencies: - Requires backend and redis services

    Restart Policy: unless-stopped

    4. Redis Service

    Image: redis:7-alpine

    Command:

    redis-server --appendonly no --save ""

    Key Features: - No persistence (in-memory only) - Fast message queue - Used for Celery broker and result backend - Used for pub/sub (progress updates)

    Ports: - 6379:6379 - Exposed to host for debugging

    Restart Policy: unless-stopped

    5. Nginx Service

    Image: nginx:alpine

    Volumes: - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro - Configuration - ./certbot/conf:/etc/letsencrypt:ro - SSL certificates - ./certbot/www:/var/www/certbot:ro - Let's Encrypt challenges

    Ports: - 80:80 - HTTP - 443:443 - HTTPS

    Dependencies: - backend, frontend

    Restart Policy: unless-stopped

    Network Configuration

    Bridge Network: nolain-network

    Service Hostnames: - backend → backend:8000 - frontend → frontend:80 - redis → redis:6379 - nginx → nginx:80/443 - celery_worker → (no network endpoint)

    DNS Resolution: Docker provides automatic DNS resolution between services using service names.

    Nginx Configuration

    Local Development (nginx-local.conf or nginx.conf)

    upstream backend {
    server backend:8000;
}

upstream frontend {
    server frontend:80;
}

server {
    listen 80;
    server_name localhost;
    client_max_body_size 50M;

    location / {
        proxy_pass http://frontend;
        proxy_set_header Host $host;
        proxy_set_header X-User-ID $http_x_user_id;
        proxy_set_header X-Access-Token $http_x_access_token;
    }

    location /api/ {
        rewrite ^/api/(.*)$ /$1 break;
        proxy_pass http://backend;
        proxy_set_header X-User-ID $http_x_user_id;
        proxy_set_header X-Access-Token $http_x_access_token;
    }

    # Stripe webhooks (stripe listen --forward-to http://localhost/webhook)
    location = /webhook {
        proxy_pass http://backend/webhook;
    }

    location /health {
        proxy_pass http://backend/;
    }
}

    Production (nginx-production.conf)

    # HTTP → HTTPS redirect
server {
    listen 80;
    server_name nolainocr.com www.nolainocr.com;

    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    location / {
        return 301 https://$server_name$request_uri;
    }
}

# HTTPS server
server {
    listen 443 ssl http2;
    server_name nolainocr.com www.nolainocr.com;

    ssl_certificate /etc/letsencrypt/live/nolainocr.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/nolainocr.com/privkey.pem;

    ssl_protocols TLSv1.2 TLSv1.3;

    # Security headers
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;

    client_max_body_size 100M;

    # Extended timeouts for long-running API requests
    proxy_read_timeout 300s;
    proxy_connect_timeout 300s;
    proxy_send_timeout 300s;

    location / {
        proxy_pass http://frontend;
        # No-cache for HTML files
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    location /api/ {
        rewrite ^/api/(.*)$ /$1 break;
        proxy_pass http://backend;
    }

    location = /webhook {
        proxy_pass http://backend/webhook;
    }
}

    Frontend SPA Routing (frontend/nginx.conf)

    server {
    listen 80;
    server_name localhost;
    root /usr/share/nginx/html;
    index index.html;

    # No cache for index.html
    location = /index.html {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    # Aggressive caching for static assets
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # SPA routing: all routes → index.html
    location / {
        try_files $uri $uri/ /index.html;
    }
}

    SSL/TLS Configuration

    Certificate Acquisition

    Using Certbot Docker Container:

    docker run -it --rm \
  -v "$(pwd)/certbot/conf:/etc/letsencrypt" \
  -v "$(pwd)/certbot/www:/var/www/certbot" \
  certbot/certbot certonly \
  --webroot \
  --webroot-path=/var/www/certbot \
  --email YOUR_EMAIL@example.com \
  --agree-tos \
  --no-eff-email \
  -d nolainocr.com \
  -d www.nolainocr.com

    Certificate Files: - fullchain.pem - Certificate chain - privkey.pem - Private key - cert.pem - Certificate only - chain.pem - Chain only

    Location: ./certbot/conf/live/nolainocr.com/

    Auto-Renewal

    Cron Job:

    0 0,12 * * * cd /path/to/project && docker run --rm \
  -v "$(pwd)/certbot/conf:/etc/letsencrypt" \
  -v "$(pwd)/certbot/www:/var/www/certbot" \
  certbot/certbot renew && \
  docker-compose restart nginx >> /var/log/ssl-renewal.log 2>&1

    Schedule: Twice daily (midnight and noon)

    Deployment Scenarios

    Local Development (Docker Compose)

    Start:

    docker-compose up -d --build

    Access: - Frontend: http://localhost - Backend API: http://localhost/api - Direct backend: http://localhost:8000 (if port exposed)

    Configuration: - Use nginx/nginx.conf (local config) - FRONTEND_URL=http://localhost - Test mode Stripe keys

    Production (VPS)

    Prerequisites: 1. Domain pointing to VPS IP 2. SSL certificates obtained 3. Production environment variables

    Start:

    docker-compose down
docker-compose up -d --build

    Access: - Frontend: https://nolainocr.com - Backend API: https://nolainocr.com/api

    Configuration: - Use nginx/nginx-production.conf - FRONTEND_URL=https://nolainocr.com - Live mode Stripe keys

    Maintenance Mode

    Enable:

    cp nginx/nginx-maintenance.conf nginx/nginx.conf
docker-compose restart nginx

    Result: Returns 503 status with maintenance page

    Resource Considerations

    Disk Space

    • Backend Data: Varies with usage, files cleaned on logout
    • Redis: In-memory only, minimal disk
    • Docker Images: ~2GB total
    • Logs: Grows over time, rotate recommended

    Memory

    • Backend: ~200MB baseline
    • Frontend: ~50MB (static files only)
    • Celery Worker: ~300MB with loaded models
    • Redis: ~50MB baseline, grows with queue
    • Nginx: ~10MB

    Total: ~600MB minimum, ~1-2GB with activity

    CPU

    • Most Services: Minimal CPU when idle
    • Celery Worker: High CPU during extraction tasks
    • Backend: Spikes during API calls

    Backup Strategy

    What to Backup

    1. Backend data directory: ./backend/data/ (if needed)
    2. Supabase database: Use Supabase backups
    3. SSL certificates: ./certbot/conf/ (can be regenerated)
    4. Environment variables: .env file (store securely)
    5. Nginx configs: ./nginx/ directory

    What NOT to Backup

    • Docker images (can be rebuilt)
    • Redis data (volatile, queue only)
    • Node modules (can be reinstalled)

    Security Considerations

    1. HTTPS Only: Production uses HTTPS with HSTS
    2. Security Headers: X-Frame-Options, X-Content-Type-Options, etc.
    3. Environment Secrets: Never commit .env to git
    4. Firewall: Only ports 80, 443, 22 open
    5. Container Isolation: Services in isolated network
    6. Read-only Volumes: Nginx configs mounted as :ro
