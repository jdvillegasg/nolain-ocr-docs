    Layer Breakdown

    1. API Layer (api/api_v1/)

    Entry point for all HTTP requests. The backend has no /api prefix — nginx strips /api before forwarding. API_V1_STR in config is empty.

    Main Router (api.py)

    api_router.include_router(health.router, tags=["health"])
api_router.include_router(auth.router, tags=["auth"])
api_router.include_router(documents.router, tags=["documents"])
api_router.include_router(payments.router, tags=["payments"])
api_router.include_router(topup_billing.router, tags=["topup-billing"])
api_router.include_router(sse.router, tags=["sse"])

    Endpoint Modules

    health.py - GET / - Health check

    auth.py - Authentication & User Management - POST /login - Email/password login - POST /register - User registration - GET /auth/google - Google OAuth redirect URL - POST /auth/session - Verify OAuth tokens after callback - POST /logout - Logout and file cleanup (auth required) - POST /reset-password - Request password reset - POST /update-password - Update password with recovery tokens

    documents.py - Document Processing - POST /upload_pdf - Upload PDF(s), convert to page images - POST /upload_image - Upload image file(s) - GET /get_page_image/{folder_id}/{page_number} - Preview pages - POST /extract_image - Synchronous single-image extraction - POST /extract_multiple_images - Async batch extraction (returns task_id) - POST /export_current_data - Export current table data as Excel or CSV

    payments.py - Subscription Management - POST /create-checkout-session - Start Stripe subscription checkout - POST /webhook - Stripe webhook handler - GET /subscription-limits - Plan limits for all tiers - GET /subscription-status - Current plan, usage, top-up balance (auth required) - POST /cancel-subscription - Cancel at period end (auth required) - POST /create-billing-portal-session - Stripe Customer Portal (auth required) - POST /update-subscription - Upgrade/downgrade plan (auth required)

    topup_billing.py - One-time Page Packs - GET /topup-packs - Catalog of available top-up packs - POST /create-topup-checkout - Start Stripe checkout for page credits - POST /confirm-topup-checkout - Confirm paid session and credit pages

    sse.py - Real-time Updates - GET /stream/{task_id} - SSE stream for Celery extraction progress

    Auth Dependencies (dependencies/auth.py)

    Protected endpoints require one of: - X-Access-Token header (Supabase JWT — preferred) - X-User-Id header (fallback)

    Returns AuthContext with user and method: "session".

    2. Service Layer (services/)

    Business logic layer. Separates API concerns from implementation.

    auth_service.py

    • User registration and login via Supabase Auth
    • Google OAuth URL generation and session verification
    • Password reset and update flows
    • Logout with upload file cleanup

    upload_service.py

    • PDF and image upload handling
    • PDF to JPEG conversion (pdf2image/Poppler)
    • Page limit validation before upload
    • Page image serving for preview
    • Tracks file paths in user_sessions table

    extraction_service.py

    • Single image: synchronous Mistral vision extraction in the API process
    • Multiple images: queues Celery task, returns task_id immediately
    • Template grouping (combine up to 4 pages per document)
    • Schema extraction from first page, then batch processing of remaining pages

    export_service.py

    • Excel and CSV export from current extraction table data
    • Background task cleanup of temporary export files

    payment_service.py

    • Stripe checkout session creation (subscriptions and top-ups)
    • Subscription status, cancellation, plan changes
    • Billing portal access
    • Webhook event processing

    Webhook Events Handled: - checkout.session.completed - Create subscription or credit top-up pages - customer.subscription.updated - Update subscription - customer.subscription.deleted - Cancel subscription - invoice.payment_succeeded - Reset monthly usage counter

    page_billing_service.py

    • Bills processed pages after extraction completes
    • Priority: monthly plan quota first, then top-up credits
    • Returns 402 if both pools exhausted
    • Admin users (ADMIN_USER_ID) bypass limits

    billing_service.py

    • Billing mode helpers (subscription + top-up can coexist)

    3. Data Pipeline (data_pipeline/)

    extraction_pipeline.py

    • Mistral AI vision API calls (single and batch)
    • Parallel async extraction for <50 images
    • Mistral Batch API for ≥50 images
    • JSON parsing and schema enforcement

    key_standardization.py

    • Flatten nested dictionaries
    • Key normalization (lowercase, underscores)
    • extract_schema() from first extraction result
    • Sentence transformers (all-MiniLM-L6-v2) for key similarity matching

    type_conversion.py

    • String to number/date coercion for export

    file_utils.py / image_utils.py

    • PDF page counting and conversion
    • Base64 image encoding
    • Multi-page image combining (template groups)

    storage.py

    • Excel generation (openpyxl)
    • CSV generation

    supabase_client.py

    • All database operations (subscriptions, user_sessions, topup_credit_purchases)
    • Three client modes: default (service role preferred), auth-only (anon key), billing client

    4. Background Tasks (tasks/extraction.py)

    Celery Task: process_extraction_task

    Flow: 1. Publish "processing" status to Redis 2. Load and group images (template_group support) 3. Extract schema from first page 4. Process remaining pages (parallel or batch API) 5. Convert results to columnar format 6. Bill processed pages via page_billing_service 7. Publish "completed" or "failed" status with results

    5. Core Infrastructure (core/)

    config.py

    Key settings: Supabase credentials, Mistral API key, Stripe keys/price IDs, subscription limits, Celery/Redis URLs, FRONTEND_URL, ADMIN_USER_ID.

    Subscription Limits (backend defaults):

    FREE_PAGES_PER_DOCUMENT = 3
FREE_PAGES_PER_MONTH = 3
PRO_PAGES_PER_DOCUMENT = 50
PRO_PAGES_PER_MONTH = 1500
PRO_PLUS_PAGES_PER_DOCUMENT = 200
PRO_PLUS_PAGES_PER_MONTH = 10000

    celery_app.py

    • Broker and result backend: Redis
    • Task discovery: backend.tasks
    • Serializer: JSON

    redis_client.py

    • Pub/Sub channels: task_updates:{task_id}

    clients.py

    • Singleton Mistral AI client

    6. Layout Module (layout/) — Experimental

    YOLO-based document layout detection. Not wired into the production extraction pipeline.

    Request Flow Examples

    Example 1: Single Image Extraction (Synchronous)

    1. POST /extract_image (X-Access-Token header)
   ↓
2. ExtractionService.extract_image()
   ↓
3. extraction_pipeline: Mistral vision API call
   ↓
4. Flatten, normalize keys, convert types
   ↓
5. bill_processed_pages()
   ↓
6. Return extracted data

    Example 2: Multi-Image Extraction (Async)

    1. POST /extract_multiple_images
   ↓
2. ExtractionService.extract_multiple_images()
   ↓
3. Queue Celery task → process_extraction_task()
   ↓
4. Return task_id immediately

[Frontend connects to GET /stream/{task_id}]

[Celery Worker]
5. Extract schema from page 1
6. Batch process remaining pages
7. Bill pages, publish results to Redis
8. Frontend receives via SSE

    Key Design Patterns

    1. Service Layer Pattern: Separates API from business logic
    2. Singleton Pattern: Shared Mistral AI client
    3. Repository Pattern: supabase_client.py abstracts database
    4. Pub/Sub Pattern: Redis for real-time progress updates
    5. Task Queue Pattern: Celery for long-running operations
    6. Dual Billing Pool: Plan quota + top-up credits with priority ordering
