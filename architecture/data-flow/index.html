    Data Flow Architecture

    This document details the end-to-end data flows through the Nolain OCR system for key user workflows.

    Flow 1: User Registration and Email Verification

    sequenceDiagram
    participant User
    participant Frontend
    participant Backend
    participant Supabase
    participant Email

    User->>Frontend: Fill registration form
    Frontend->>Backend: POST /register
    Backend->>Supabase: Create user account
    Supabase-->>Backend: User created
    Backend->>Supabase: Create free subscription record
    Supabase->>Email: Send verification email
    Backend-->>Frontend: Registration success
    Frontend-->>User: Show "Check your email"

    User->>Email: Click verification link
    Email->>Frontend: Redirect to / with tokens
    Frontend->>Frontend: Detect verification tokens
    Frontend->>Frontend: Redirect to /registration-success
    Frontend-->>User: "Email verified! Sign in"

    Flow 2: User Login (Email/Password)

    sequenceDiagram
    participant User
    participant Frontend
    participant Backend
    participant Supabase

    User->>Frontend: Enter email/password
    Frontend->>Backend: POST /login
    Backend->>Supabase: Authenticate user
    Supabase-->>Backend: User data + access_token
    Backend-->>Frontend: User data + access_token
    Frontend->>Frontend: Store in authStore
    Frontend->>Frontend: Redirect to /dashboard
    Frontend-->>User: Dashboard page

    Subsequent API calls include headers: - X-Access-Token: {access_token} - X-User-Id: {user_id}

    Flow 2b: Google OAuth Login

    sequenceDiagram
    participant User
    participant Frontend
    participant Supabase
    participant Backend

    User->>Frontend: Click "Sign in with Google"
    Frontend->>Supabase: signInWithOAuth (Google)
    Supabase-->>User: Google consent screen
    User->>Supabase: Authorize
    Supabase->>Frontend: Redirect to /auth/callback?code=...
    Frontend->>Backend: POST /auth/session (tokens)
    Backend->>Supabase: Verify tokens
    Backend-->>Frontend: User data
    Frontend->>Frontend: Store in authStore
    Frontend-->>User: Redirect to /dashboard

    Flow 3: Document Upload (Single Page)

    sequenceDiagram
    participant User
    participant Frontend
    participant Backend
    participant Supabase
    participant Filesystem

    User->>Frontend: Select PDF/image file
    Frontend->>Backend: POST /upload_pdf (X-Access-Token)
    Backend->>Supabase: Check subscription limits
    Backend->>Backend: Validate page count
    Backend->>Filesystem: Save file to data/
    Backend->>Supabase: Update user_sessions (file_paths)
    Backend-->>Frontend: file_id (filename)
    Frontend->>Frontend: Store in dashboardStore
    Frontend-->>User: Show preview + extract options

    Flow 4: Document Upload (Multi-Page)

    sequenceDiagram
    participant User
    participant Frontend
    participant Backend
    participant Supabase
    participant Filesystem

    User->>Frontend: Select multiple files or multi-page PDF
    Frontend->>Backend: POST /upload_pdf (multiple files)
    Backend->>Supabase: Check subscription limits
    Backend->>Backend: Validate total page count
    Backend->>Filesystem: Create folder upload_{user_id}_{timestamp}/
    Backend->>Filesystem: Convert PDF pages to page_N.jpg
    Backend->>Supabase: Update user_sessions (file_paths)
    Backend-->>Frontend: file_id (folder name)
    Frontend->>Backend: GET /get_page_image/{folder_id}/{n}
    Backend-->>Frontend: Page image URLs
    Frontend-->>User: Show page grid + template config

    Folder Structure:

    backend/data/
└── upload_{user_id}_{timestamp}/
    ├── page_1.jpg
    ├── page_2.jpg
    └── ...

    Flow 5: Single Image Extraction (Synchronous)

    sequenceDiagram
    participant User
    participant Frontend
    participant Backend
    participant MistralAI
    participant Supabase

    User->>Frontend: Click "Extract"
    Frontend->>Backend: POST /extract_image
    Backend->>Backend: Load and encode image
    Backend->>MistralAI: Vision API call
    MistralAI-->>Backend: JSON structured data
    Backend->>Backend: Flatten, normalize keys, convert types
    Backend->>Supabase: bill_processed_pages()
    Backend-->>Frontend: Extracted data
    Frontend->>Frontend: Store in dashboardStore
    Frontend-->>User: Display in DataTable

    Flow 6: Multi-Image Extraction (Async with SSE)

    sequenceDiagram
    participant User
    participant Frontend
    participant Backend
    participant Redis
    participant Celery
    participant MistralAI
    participant Supabase

    User->>Frontend: Click "Extract All"
    Frontend->>Backend: POST /extract_multiple_images
    Backend->>Redis: Queue Celery task
    Backend-->>Frontend: task_id
    Frontend->>Backend: GET /stream/{task_id} (SSE)
    Backend->>Redis: Subscribe to task_updates:{task_id}

    Celery->>Redis: Pick up task
    Celery->>Redis: Publish "processing"
    Redis-->>Backend: Status update
    Backend-->>Frontend: SSE: processing
    Frontend-->>User: Show progress bar

    Celery->>MistralAI: Extract schema from page 1
    Celery->>MistralAI: Batch/parallel process remaining pages
    Celery->>Redis: Publish progress %
    Redis-->>Backend: Progress update
    Backend-->>Frontend: SSE: progress

    Celery->>Supabase: bill_processed_pages()
    Celery->>Redis: Publish "completed" with results
    Redis-->>Backend: Final status
    Backend-->>Frontend: SSE: completed + data
    Frontend-->>User: Display results

    Flow 7: Export Current Data

    sequenceDiagram
    participant User
    participant Frontend
    participant Backend

    User->>Frontend: Click "Export" (Excel/CSV/JSON)

    alt JSON export
        Frontend->>Frontend: Client-side download
    else Excel or CSV
        Frontend->>Backend: POST /export_current_data
        Backend->>Backend: Generate file (openpyxl or CSV)
        Backend-->>Frontend: File download
    end

    Frontend-->>User: Browser downloads file

    Google Sheets export is handled entirely client-side via the Google API.

    Flow 8: Subscription Purchase

    sequenceDiagram
    participant User
    participant Frontend
    participant Backend
    participant Stripe
    participant Supabase

    User->>Frontend: Click "Upgrade to Pro"
    Frontend->>Backend: POST /create-checkout-session
    Backend->>Stripe: Create checkout session
    Stripe-->>Backend: Session URL
    Backend-->>Frontend: Redirect URL
    Frontend->>Stripe: Redirect to Stripe Checkout
    User->>Stripe: Complete purchase

    Stripe->>Backend: POST /webhook (checkout.session.completed)
    Backend->>Supabase: UPDATE subscriptions table
    Backend-->>Stripe: 200 OK

    Stripe->>Frontend: Redirect to success URL
    Frontend->>Backend: GET /subscription-status
    Backend-->>Frontend: Updated plan + limits
    Frontend-->>User: "Subscription activated!"

    Flow 9: Top-up Page Pack Purchase

    sequenceDiagram
    participant User
    participant Frontend
    participant Backend
    participant Stripe
    participant Supabase

    User->>Frontend: Select top-up pack on /account
    Frontend->>Backend: POST /create-topup-checkout
    Backend->>Stripe: Create one-time checkout session
    Stripe-->>Backend: Session URL
    Frontend->>Stripe: Redirect to checkout
    User->>Stripe: Complete payment

    Stripe->>Backend: POST /webhook (checkout.session.completed)
    Backend->>Supabase: Credit topup_page_credits

    Stripe->>Frontend: Redirect to /account?topup=success
    Frontend->>Backend: POST /confirm-topup-checkout
    Backend->>Supabase: Idempotent credit confirmation
    Frontend-->>User: Updated credit balance

    Flow 10: Password Reset

    sequenceDiagram
    participant User
    participant Frontend
    participant Backend
    participant Supabase
    participant Email

    User->>Frontend: Click "Forgot password?"
    User->>Frontend: Enter email
    Frontend->>Backend: POST /reset-password
    Backend->>Supabase: Request password reset
    Supabase->>Email: Send reset email
    Backend-->>Frontend: Success
    Frontend-->>User: "Check your email"

    User->>Email: Click reset link
    Email->>Frontend: Redirect to /reset-password?access_token=...
    User->>Frontend: Enter new password
    Frontend->>Backend: POST /update-password
    Backend->>Supabase: Update password with tokens
    Backend-->>Frontend: Success
    Frontend-->>User: "Password updated! Please log in"

    Flow 11: Logout and File Cleanup

    sequenceDiagram
    participant User
    participant Frontend
    participant Backend
    participant Supabase
    participant Filesystem

    User->>Frontend: Click logout
    Frontend->>Backend: POST /logout (X-Access-Token)
    Backend->>Supabase: Query user_sessions (file_paths)
    Backend->>Filesystem: Delete all upload folders
    Backend->>Supabase: Delete user_sessions entry
    Backend-->>Frontend: Success
    Frontend->>Frontend: Clear authStore + dashboardStore
    Frontend-->>User: Redirect to landing page

    Data Persistence Locations

    Frontend (Browser)

    • LocalStorage:
    • auth-storage: User session, access token
    • dashboard-storage: Upload state, extraction results
    • tutorial-seen: First-time tutorial flag

    Backend (Filesystem)

    • backend/data/: Uploaded files (temporary, cleaned on logout)

    Database (Supabase)

    • auth.users: User accounts (Supabase Auth)
    • subscriptions: Plan tier, usage, Stripe IDs, top-up credits
    • user_sessions: Active upload file paths (file_paths JSONB)
    • topup_credit_purchases: Idempotent top-up purchase records

    Cache (Redis)

    • Task Queue: Celery task messages
    • Result Backend: Task results (temporary)
    • Pub/Sub: task_updates:{task_id} for SSE progress

    Data Transformations

    PDF → Images

    Input: document.pdf (5 pages)
  ↓ pdf2image (Poppler)
Output: page_1.jpg, page_2.jpg, ..., page_5.jpg

    AI Extraction → Columnar Data

    Input: Image (base64) → Mistral Vision API → JSON per page
  ↓ Flatten nested dicts, normalize keys, convert types
  ↓ extract_schema() from first page
  ↓ Batch process remaining pages with same schema
Output: { field_name: [val1, val2, ...], filenames: [...] }

    Performance Characteristics

    Synchronous (< 30s)

    • Single image extraction
    • File uploads (< 50MB)
    • Login/logout
    • Subscription status queries
    • Export current data

    Asynchronous (30s - 15min)

    • Multi-image batch extraction (returns task_id, progress via SSE)
    • Large jobs (≥50 images) use Mistral Batch API

    Real-time (< 100ms)

    • SSE progress updates via Redis pub/sub
    • Page preview loading
