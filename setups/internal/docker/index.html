    Docker Setup Guide

    This document explains the process of dockerizing and running the Nolain OCR application using Docker and Docker Compose.

    Table of Contents

    • Overview
    • Architecture
    • Prerequisites
    • Environment Variables
    • Building Docker Images
    • Running the Application
    • Service Details
    • Troubleshooting

    Overview

    The application is containerized using Docker and orchestrated with Docker Compose. It consists of three main services:

    1. Backend: FastAPI application running on Python 3.11
    2. Frontend: React/TypeScript application built with Vite and served via Nginx
    3. Nginx: Reverse proxy handling routing and SSL termination

    Architecture

    ┌─────────────────┐
│   Nginx (443)   │ ← External access
└────────┬────────┘
         │
    ┌────┴────┐
    │         │
┌───▼───┐ ┌──▼──────┐
│Frontend│ │ Backend │
│  :80  │ │  :8000  │
└───────┘ └─────────┘
    • Nginx listens on ports 80 (HTTP) and 443 (HTTPS)
    • Frontend serves static files on port 80 (internal)
    • Backend API runs on port 8000 (internal)
    • All services communicate through a Docker bridge network

    Prerequisites

    Before starting, ensure you have the following installed:

    • Docker (version 20.10 or higher)
    • Docker Compose (version 1.29 or higher)
    • Git (to clone the repository)

    Verify your installation:

    docker --version
docker-compose --version

    Environment Variables

    Create a .env file in the project root with the following variables:

    # Supabase Configuration
SUPABASE_URL=your_supabase_url
SUPABASE_ANON_KEY=your_supabase_anon_key

# Mistral AI Configuration
MISTRAL_API_KEY=your_mistral_api_key

# Stripe Configuration
STRIPE_SECRET_KEY=your_stripe_secret_key
STRIPE_WEBHOOK_SECRET=your_stripe_webhook_secret

# Frontend URL (for CORS and redirects)
FRONTEND_URL=https://nolainocr.com

    Note: For local development, you may want to set FRONTEND_URL=http://localhost or adjust the nginx configuration accordingly.

    Building Docker Images

    Option 1: Build All Services with Docker Compose

    Build all services at once:

    docker-compose build

    Build without cache (useful for fresh builds):

    docker-compose build --no-cache

    Option 2: Build Individual Services

    Build only the backend:

    docker-compose build backend

    Build only the frontend:

    docker-compose build frontend

    Understanding the Build Process

    Backend Dockerfile

    The backend uses a multi-stage approach:

    1. Base Image: python:3.11-slim
    2. System Dependencies: Installs poppler-utils for PDF processing
    3. Python Dependencies: Installs packages from requirements.txt
    4. Application Code: Copies the backend directory
    5. Runtime: Runs with uvicorn on port 8000

    Key features: - Optimized layer caching (requirements copied first) - Data directory created for file uploads - Exposes port 8000 internally

    Frontend Dockerfile

    The frontend uses a multi-stage build:

    1. Builder Stage:
    2. Uses node:18-alpine as base
    3. Installs dependencies with npm ci

    4. Builds the production bundle with npm run build

    5. Production Stage:

    6. Uses nginx:alpine for serving static files
    7. Copies built files from builder stage
    8. Includes nginx configuration for SPA routing

    Key features: - Multi-stage build reduces final image size - Production-optimized build - Nginx configured for React Router (SPA routing)

    Running the Application

    Start All Services

    Start all services in detached mode:

    docker-compose up -d

    Start with logs visible:

    docker-compose up

    Stop Services

    Stop all services:

    docker-compose down

    Stop and remove volumes (⚠️ removes data):

    docker-compose down -v

    View Logs

    View logs from all services:

    docker-compose logs -f

    View logs from a specific service:

    docker-compose logs -f backend
docker-compose logs -f frontend
docker-compose logs -f nginx

    Restart Services

    Restart all services:

    docker-compose restart

    Restart a specific service:

    docker-compose restart backend

    Service Details

    Backend Service

    • Container Name: nolain-ocr-backend
    • Internal Port: 8000
    • Working Directory: /app
    • Volumes:
    • ./backend/data:/app/backend/data (persistent data storage)
    • Environment Variables: All variables from .env file
    • Restart Policy: unless-stopped

    Access the backend API: - Internally: http://backend:8000 - Externally: https://your-domain.com/api

    Frontend Service

    • Container Name: nolain-ocr-frontend
    • Internal Port: 80
    • Restart Policy: unless-stopped

    Access the frontend: - Internally: http://frontend:80 - Externally: https://your-domain.com

    Nginx Service

    • Container Name: nolain-ocr-nginx
    • External Ports: 80 (HTTP), 443 (HTTPS)
    • Volumes:
    • ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro (nginx config)
    • ./certbot/conf:/etc/letsencrypt:ro (SSL certificates)
    • ./certbot/www:/var/www/certbot:ro (Let's Encrypt challenges)
    • Depends On: backend, frontend
    • Restart Policy: unless-stopped

    Nginx handles: - SSL/TLS termination - HTTP to HTTPS redirects - Reverse proxying to backend (/api routes) - Serving frontend static files - Let's Encrypt certificate challenges

    Troubleshooting

    Check Service Status

    docker-compose ps

    Inspect a Container

    docker inspect nolain-ocr-backend
docker inspect nolain-ocr-frontend
docker inspect nolain-ocr-nginx

    Execute Commands in Containers

    Access backend container shell:

    docker-compose exec backend bash

    Access frontend container shell:

    docker-compose exec frontend sh

    Common Issues

    Port Already in Use

    If ports 80 or 443 are already in use:

    # Find process using port 80
sudo lsof -i :80

# Find process using port 443
sudo lsof -i :443

    Stop the conflicting service or modify docker-compose.yml to use different ports.

    Environment Variables Not Loading

    Ensure your .env file is in the project root and contains all required variables:

    # Verify .env file exists
ls -la .env

# Check if variables are loaded
docker-compose config

    Build Failures

    Clear Docker cache and rebuild:

    docker-compose down
docker system prune -a
docker-compose build --no-cache

    Frontend Not Updating

    Rebuild the frontend after code changes:

    docker-compose build frontend
docker-compose up -d frontend

    Backend Connection Issues

    Check if backend is running:

    docker-compose logs backend
docker-compose exec backend curl http://localhost:8000/health

    Nginx Configuration Errors

    Test nginx configuration:

    docker-compose exec nginx nginx -t

    Reload nginx after config changes:

    docker-compose exec nginx nginx -s reload

    Health Checks

    Check if services are responding:

    # Backend health
curl http://localhost/api/health

# Frontend
curl http://localhost

    View Resource Usage

    docker stats

    Clean Up

    Remove all containers, networks, and images:

    docker-compose down --rmi all

    Remove unused Docker resources:

    docker system prune -a --volumes

    Development Workflow

    Making Changes

    1. Backend Changes: bash # After modifying backend code docker-compose build backend docker-compose up -d backend

    2. Frontend Changes: bash # After modifying frontend code docker-compose build frontend docker-compose up -d frontend

    3. Nginx Configuration Changes: bash # After modifying nginx.conf docker-compose restart nginx # Or reload without restart docker-compose exec nginx nginx -s reload

    Hot Reloading (Development)

    For development with hot reloading, you may want to run services locally instead of in Docker, or mount volumes for live code updates (requires additional docker-compose configuration).

    Production Considerations

    1. SSL Certificates: Ensure Let's Encrypt certificates are properly configured
    2. Environment Variables: Use secure secret management in production
    3. Data Persistence: Backend data directory is mounted as a volume
    4. Logging: Consider setting up centralized logging
    5. Monitoring: Add health checks and monitoring tools
    6. Backup: Implement regular backups of the data directory
    7. Resource Limits: Consider adding resource limits in docker-compose.yml:
    services:
  backend:
    deploy:
      resources:
        limits:
          cpus: '2'
          memory: 2G
