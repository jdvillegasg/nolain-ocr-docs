    Local vs Production Testing Guide

    This guide explains how to switch between local development and production deployment while keeping your domain configuration intact. This allows you to block public access to your website during development without undoing your DNS and SSL setup.

    Overview

    Your website is currently configured with: - Domain: nolainocr.com pointing to your VPS IP - SSL certificates configured - Docker Compose setup with nginx, backend, and frontend services

    This guide provides methods to: 1. Block public access to your production site (maintenance mode) 2. Test locally on your development machine 3. Switch back to production when ready 4. Keep DNS and SSL configuration intact throughout

    Method 1: Nginx Maintenance Mode (Recommended)

    This method uses a maintenance nginx configuration that blocks all public access while keeping SSL certificates and DNS intact.

    ⚠️ Important: If maintenance mode doesn't work after switching, see the Troubleshooting section below. Common issues are browser caching and nginx not reloading properly.

    Enable Maintenance Mode (Block Public Access)

    On your VPS:

    1. SSH into your VPS:
    ssh user@your-vps-ip
    1. Navigate to your project directory:
    cd /path/to/your/project
    1. Backup current nginx config:
    cp nginx/nginx.conf nginx/nginx.conf.production
    1. Switch to maintenance mode:
    cp nginx/nginx-maintenance.conf nginx/nginx.conf
    1. Verify nginx config is valid:
    docker exec nolain-ocr-nginx nginx -t
# Should show: "syntax is ok" and "test is successful"
    1. Force reload nginx (use reload instead of restart for zero downtime):
    docker exec nolain-ocr-nginx nginx -s reload
# OR if reload doesn't work, force restart:
docker-compose restart nginx
    1. Verify maintenance mode is active (use curl, not browser):
    curl -k https://nolainocr.com
# Should return HTML with "Site Under Maintenance"
curl -I -k https://nolainocr.com
# Should show: HTTP/1.1 503 Service Unavailable

    Important: If you're testing in a browser, you may see cached content. Always test with curl first, or use: - Chrome/Edge: Ctrl+Shift+R (Cmd+Shift+R on Mac) for hard refresh - Firefox: Ctrl+F5 (Cmd+Shift+R on Mac) - Or open in incognito/private mode

    Result: Your domain will now show a "Site Under Maintenance" message to all visitors. DNS and SSL remain configured.

    Disable Maintenance Mode (Restore Production)

    On your VPS:

    1. Restore production config:
    cp nginx/nginx.conf.production nginx/nginx.conf
    1. Verify nginx config is valid:
    docker exec nolain-ocr-nginx nginx -t
    1. Force reload nginx:
    docker exec nolain-ocr-nginx nginx -s reload
# OR if reload doesn't work:
docker-compose restart nginx
    1. Verify production is active:
    curl -k https://nolainocr.com
# Should return your website content
curl -I -k https://nolainocr.com
# Should show: HTTP/1.1 200 OK

    Method 2: Firewall Rules (Alternative)

    This method blocks external access at the firewall level while allowing local VPS access.

    Block Public Access with Firewall

    On your VPS:

    1. Check current firewall status:
    sudo ufw status
    1. Block external access to ports 80 and 443:
    # Remove public access rules
sudo ufw delete allow 80/tcp
sudo ufw delete allow 443/tcp

# Or if you want to keep them but restrict to specific IPs:
# sudo ufw delete allow 80/tcp
# sudo ufw delete allow 443/tcp
# sudo ufw allow from YOUR_IP_ADDRESS to any port 80
# sudo ufw allow from YOUR_IP_ADDRESS to any port 443
    1. Verify firewall rules:
    sudo ufw status verbose

    Result: External visitors cannot access your site, but DNS and SSL remain configured.

    Restore Public Access

    On your VPS:

    1. Re-enable public access:
    sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
    1. Verify:
    sudo ufw status

    Method 3: Stop Docker Services (Simple but Complete Shutdown)

    This method completely stops your services while keeping all configurations intact.

    Stop Production Services

    On your VPS:

    1. Stop all services:
    cd /path/to/your/project
docker-compose down

    Result: Your website will be completely inaccessible, but all configurations (DNS, SSL, nginx configs) remain unchanged.

    Start Production Services

    On your VPS:

    1. Start all services:
    docker-compose up -d
    1. Verify services are running:
    docker-compose ps

    Local Development Setup

    Prerequisites

    • Node.js and npm installed locally
    • Python 3.8+ installed locally
    • Access to your environment variables (Supabase, Stripe, etc.)

    Running Frontend Locally

    1. Navigate to frontend directory:
    cd frontend
    1. Install dependencies (if not already done):
    npm install
    1. Start development server:
    npm run dev
    1. Access frontend:
    2. Open http://localhost:5173 (or the port shown in terminal)

    Running Backend Locally

    1. Navigate to backend directory:
    cd backend
    1. Create virtual environment (if not exists):
    python3 -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate
    1. Install dependencies:
    pip install -r requirements.txt
    1. Set environment variables:
    2. Create a .env file or export variables:
    export SUPABASE_URL="your-supabase-url"
export SUPABASE_ANON_KEY="your-anon-key"
export MISTRAL_API_KEY="your-mistral-key"
export STRIPE_SECRET_KEY="your-stripe-secret"
export STRIPE_WEBHOOK_SECRET="your-webhook-secret"
export FRONTEND_URL="http://localhost:5173"
    1. Start backend server:
    uvicorn main:app --reload --host 0.0.0.0 --port 8000
    1. Access backend:
    2. API will be available at http://localhost:8000
    3. API docs at http://localhost:8000/docs

    Important Notes for Local Development

    • CORS Configuration: Your backend's CORS settings should already allow http://localhost (check backend/main.py)
    • API Base URL: The frontend uses /api which works with a proxy. For local dev, you may need to configure Vite proxy or update api.ts to use http://localhost:8000/api
    • Environment Variables: Make sure to use development/test API keys when testing locally

    Configure Vite Proxy for Local Development (Optional)

    If you want the frontend to proxy API requests to your local backend:

    1. Edit frontend/vite.config.ts:
    export default defineConfig({
  // ... existing config
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8000',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, ''),
      },
    },
  },
})

    Quick Reference: Switching Between Modes

    Scenario 1: Block Public Access, Keep Config Intact

    # On VPS
cp nginx/nginx-maintenance.conf nginx/nginx.conf
docker exec nolain-ocr-nginx nginx -t  # Verify config
docker exec nolain-ocr-nginx nginx -s reload  # Reload nginx
# OR if reload doesn't work:
docker-compose restart nginx
# Test with curl (not browser):
curl -I -k https://nolainocr.com  # Should show 503

    Scenario 2: Restore Public Access

    # On VPS
cp nginx/nginx.conf.production nginx/nginx.conf
docker-compose restart nginx

    Scenario 3: Complete Shutdown

    # On VPS
docker-compose down

    Scenario 4: Start Production

    # On VPS
docker-compose up -d

    Scenario 5: Local Development

    # Terminal 1 - Frontend
cd frontend
npm run dev

# Terminal 2 - Backend
cd backend
source venv/bin/activate
uvicorn main:app --reload --port 8000

    Verification Checklist

    When Maintenance Mode is Active:

    • [ ] curl https://nolainocr.com returns "Site Under Maintenance"
    • [ ] Browser shows maintenance message
    • [ ] DNS still resolves correctly: dig nolainocr.com
    • [ ] SSL certificates are still valid (no certificate errors)

    When Production is Active:

    • [ ] Website loads normally at https://nolainocr.com
    • [ ] All API endpoints work correctly
    • [ ] SSL certificate is valid (padlock icon in browser)

    When Testing Locally:

    • [ ] Frontend runs on http://localhost:5173
    • [ ] Backend runs on http://localhost:8000
    • [ ] Frontend can communicate with backend
    • [ ] No CORS errors in browser console

    Troubleshooting

    Maintenance Mode Not Working (Shows Landing Page Instead)

    If maintenance mode doesn't work after switching, follow these steps:

    1. Verify the config file was actually copied:
    # Check if maintenance config is in place
grep "MAINTENANCE MODE\|Site Under Maintenance" nginx/nginx.conf
# Should show the maintenance content
    1. Check if nginx is using the correct config:
    # Test nginx config syntax
docker exec nolain-ocr-nginx nginx -t

# View the actual config nginx is using
docker exec nolain-ocr-nginx cat /etc/nginx/conf.d/default.conf | grep -A 5 "location /"
    1. Force a complete nginx restart (not just reload):
    # Stop nginx completely
docker-compose stop nginx

# Start it again
docker-compose start nginx

# OR completely recreate the container
docker-compose up -d --force-recreate nginx
    1. Clear browser cache and HSTS (if testing in browser):
    2. Chrome/Edge:
      • Open DevTools (F12) → Network tab → Check "Disable cache"
      • Or: Settings → Privacy → Clear browsing data → Cached images and files
      • For HSTS: chrome://net-internals/#hsts → Delete domain security policies
    3. Firefox:
      • Ctrl+Shift+Delete → Clear cache
      • Or: about:preferences#privacy → Clear Data
    4. Safari:
      • Develop menu → Empty Caches

    5. Best: Use incognito/private mode or test with curl

    6. Test with curl (bypasses browser cache):

    # Test from your local machine (not VPS)
curl -v -k https://nolainocr.com

# Should show:
# HTTP/1.1 503 Service Unavailable
# And HTML with "Site Under Maintenance"
    1. Check nginx logs for errors:
    docker logs nolain-ocr-nginx --tail 50
# Look for any error messages
    1. Verify Docker volume is mounted correctly:
    # Check if the config file is actually mounted
docker exec nolain-ocr-nginx ls -la /etc/nginx/conf.d/
# Should show default.conf

# Compare file contents
docker exec nolain-ocr-nginx head -20 /etc/nginx/conf.d/default.conf
# Should match your nginx.conf file
    1. If still not working, try this complete reset:
    # On VPS
cd /path/to/your/project

# Ensure maintenance config is correct
cp nginx/nginx-maintenance.conf nginx/nginx.conf

# Stop everything
docker-compose down

# Start everything fresh
docker-compose up -d

# Wait a few seconds, then test
sleep 5
curl -k https://nolainocr.com

    Browser Shows Cached Content

    If your browser keeps showing the old page:

    1. Always test with curl first:
    curl -I -k https://nolainocr.com
# Check the HTTP status code (should be 503 for maintenance)
    1. Use browser developer tools:
    2. Open DevTools (F12)
    3. Go to Network tab
    4. Check "Disable cache"

    5. Hard refresh: Ctrl+Shift+R (Cmd+Shift+R on Mac)

    6. Clear HSTS cache (Chrome/Edge):

    7. Visit: chrome://net-internals/#hsts
    8. Enter your domain: nolainocr.com
    9. Click "Delete"

    Nginx Not Reloading Config

    If docker-compose restart nginx doesn't work:

    1. Use nginx reload signal:
    docker exec nolain-ocr-nginx nginx -s reload
    1. Force recreate container:
    docker-compose up -d --force-recreate nginx
    1. Check if config file is actually being read:
    # View what nginx sees
docker exec nolain-ocr-nginx nginx -T | grep -A 10 "location /"

    Local Development Issues

    • CORS errors: Check backend/main.py CORS settings
    • API not connecting: Verify backend is running on port 8000
    • Frontend not loading: Check if port 5173 is available

    DNS/SSL Issues

    • DNS not resolving: Wait for propagation or check DNS records in Hostinger
    • SSL certificate errors: Verify certificates exist: ls -la certbot/conf/live/nolainocr.com/
    • Certificate renewal: Maintenance mode allows renewal via /.well-known/acme-challenge/

    Best Practices

    1. Always backup configs before switching: bash cp nginx/nginx.conf nginx/nginx.conf.backup.$(date +%Y%m%d)

    2. Test maintenance mode before deploying: bash curl -k https://nolainocr.com

    3. Keep production configs in version control:

    4. nginx.conf - Production config

    5. nginx-maintenance.conf - Maintenance mode config

    6. Use environment-specific API keys:

    7. Production keys on VPS

    8. Development/test keys locally

    9. Monitor SSL certificate expiration:

    10. Certificates auto-renew, but verify renewal is working
    11. Check renewal logs: grep certbot /var/log/ssl-renewal.log

    Summary

    • DNS Configuration: Never needs to be changed - stays pointing to your VPS
    • SSL Certificates: Remain valid and configured regardless of mode
    • Maintenance Mode: Blocks public access while keeping infrastructure intact
    • Local Development: Run frontend and backend separately on your machine
    • Production Mode: Full access to your website via domain

    You can switch between modes anytime without affecting your domain or SSL setup!
