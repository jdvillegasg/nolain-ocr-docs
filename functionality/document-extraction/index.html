    Document Extraction Functionality

    This document details how document extraction works in the Nolain OCR system, from image processing to AI extraction and data normalization.

    Extraction Pipeline Overview

    graph LR
    Upload[Upload File] --> Validate[Validate Limits]
    Validate --> Process[Process File]
    Process --> Convert[PDF → Images]
    Convert --> Encode[Base64 Encode]
    Encode --> AI[Mistral AI Vision]
    AI --> Parse[Parse JSON]
    Parse --> Flatten[Flatten Nested Data]
    Flatten --> Normalize[Normalize Keys]
    Normalize --> Schema[Extract Schema from Page 1]
    Schema --> Batch[Batch Process Remaining Pages]
    Batch --> Columnar[Columnar Format]
    Columnar --> Bill[Bill Pages]
    Bill --> Return[Return Results]

    Extraction Mode

    The system currently supports a single extraction mode:

    Fast Extraction (fast_extraction)

    Purpose: Extract structured data from documents and return results immediately (single page) or via async task (multi-page).

    Flow (single image): 1. Upload image/PDF 2. Extract text using Mistral AI vision 3. Flatten and normalize data 4. Bill processed pages 5. Return results synchronously

    Flow (multiple images): 1. Upload files to folder 2. Queue Celery task → returns task_id 3. Extract schema from first page 4. Batch process remaining pages (parallel or Mistral Batch API) 5. Bill pages, publish results via SSE 6. Frontend receives results on /stream/{task_id}

    Example:

    POST /extract_image
{
  "file_id": "document.jpg",
  "extraction_mode": "fast_extraction",
  "user_id": "user_uuid"
}

    Mistral AI Integration

    Vision Model

    Model: mistral-small-latest (configurable via DEFAULT_AI_MODEL)

    Capabilities: - OCR text extraction - Structured JSON output - Multi-language support - Layout understanding - Table extraction

    Single Image Extraction

    Synchronous API call in the FastAPI process. Image is base64-encoded and sent to Mistral vision with a prompt to extract structured JSON.

    Response Format:

    {
  "patient_name": "John Doe",
  "date_of_birth": "15/03/1990",
  "diagnosis": "Common cold",
  "treatment_days": 3
}

    Multi-Image Processing

    < 50 images: Parallel async requests

    ≥ 50 images: Mistral Batch API for efficient large-scale processing

    Schema enforcement: First page extraction defines the schema; remaining pages are processed with the same key structure.

    Data Processing Pipeline

    1. Image Encoding

    Images converted to base64 for API transmission.

    2. JSON Parsing

    Extracts JSON from Mistral response, handling markdown code blocks.

    3. Dictionary Flattening

    Nested dictionaries flattened to dot-separated keys, then normalized to underscores.

    4. Key Normalization

    Keys lowercased, spaces replaced with underscores, special characters removed.

    5. Data Type Conversion

    String values converted to dates and numbers where appropriate.

    6. Columnar Format

    Multiple extraction results transposed to column-oriented format:

    {
  "patient_name": ["John Doe", "Jane Smith"],
  "diagnosis": ["Flu", "Cold"],
  "filenames": ["doc1.jpg", "doc2.jpg"]
}

    Template Grouping

    Combine multiple pages into a single document for extraction.

    Configuration:

    {
  "template_group": [
    ["page_1.jpg", "page_2.jpg"],
    ["page_3.jpg", "page_4.jpg", "page_5.jpg"],
    ["page_6.jpg"]
  ]
}

    Processing: - Inner lists with 2–4 images are combined vertically before extraction - Inner lists with 1 image are processed individually - Each inner list produces one extraction result

    Maximum: 4 pages per combined document

    Page Billing

    Pages are billed after extraction completes via page_billing_service:

    1. Monthly plan quota consumed first (free tier or subscription)
    2. Top-up credits consumed when monthly quota is exhausted
    3. 402 error if both pools are empty

    Admin users (ADMIN_USER_ID) bypass all limits.

    Subscription Tiers

    Tier Pages/Document Pages/Month
    Free 3 3
    Pro 50 1,500
    Pro Plus 200 10,000

    Limits are also enforced at upload time.

    Error Handling

    Error Status Description
    Invalid file format 400 Unsupported file type
    Page limit exceeded 403 Per-document or monthly limit hit
    Insufficient credits 402 Monthly quota + top-up credits exhausted
    Mistral AI error 500 API failure (retries in batch mode)
    File not found 404 Invalid file_id or folder_id
    Access denied 403 Folder ownership mismatch

    Performance Characteristics

    Scenario Time Blocking
    Single image 2–5 seconds Synchronous
    Multi-image (< 50) ~0.5–1s per image Async (SSE)
    Multi-image (≥ 50) 5–15 minutes Async (Mistral Batch API)
