    File Management Functionality

    How the system handles file uploads, storage, and cleanup.

    File Upload

    Supported Formats

    Images: - .png, .jpg / .jpeg

    Documents: - .pdf (auto-converted to page_N.jpg images)

    Upload Process

    Single Page:

    1. Validate file type
2. Check subscription limits
3. Save to backend/data/
4. Create user_sessions entry
5. Return file_id (filename)

    Multiple Pages:

    1. Validate file types
2. Check total page count vs limits
3. Create folder: upload_{user_id}_{timestamp}/
4. Convert PDFs to images
5. Save all images to folder
6. Create user_sessions entry
7. Return file_id (folder name)

    Size Limits

    Nginx Configuration: - Local: 50MB per request - Production: 100MB per request

    File Storage

    Directory Structure

    backend/data/
├── upload_{user_id}_{timestamp}/
│   ├── page_1.jpg
│   ├── page_2.jpg
│   └── page_3.jpg
├── single_image.jpg
└── another_doc.pdf

    Naming Conventions

    Folders: upload_{user_id}_{unix_timestamp}

    Images from PDFs: page_1.jpg, page_2.jpg, ...

    Direct uploads: Original filename (with conflict resolution)

    PDF Conversion

    Process

    Library: pdf2image (uses Poppler)

    Steps: 1. Load PDF file 2. Convert each page to PIL Image 3. Save as JPG (quality: 95%) 4. Store in folder

    Example:

    from pdf2image import convert_from_path

images = convert_from_path(pdf_path)
for i, image in enumerate(images):
    output_path = f"page_{i+1}.jpg"
    image.save(output_path, 'JPEG', quality=95)

    File Cleanup

    Automatic Cleanup

    Trigger: User logout (POST /logout)

    Process: 1. Query user_sessions for file_paths array 2. Delete all file/folder paths from filesystem 3. Delete user_sessions entry

    Manual Cleanup

    Not Implemented: No manual cleanup UI

    Alternative: Files deleted on next login/logout

    Page Preview

    Endpoint

    GET /get_page_image/{folder_id}/{page_number}

    Purpose: Display page thumbnails in frontend

    Example:

    GET /api/get_page_image/upload_123_456/0

    Response: JPEG image file

    Features: - Zero-based indexing (0, 1, 2, ...) - Natural sorting (page_1.jpg before page_10.jpg) - Cache headers for performance

    Storage Considerations

    Disk Space

    Usage: Varies with user activity

    Cleanup: Files removed on logout

    Growth: Temporary, not persistent

    Backup

    Files: Temporary, not backed up

    Database: Supabase handles backups

    SSL Certs: Can be regenerated

    Security

    User Isolation: - Folders named with user_id - Sessions queried by user_id - No cross-user access

    Path Traversal Prevention: - Validate folder_id format - Check folder exists in user's sessions - Sanitize file paths
