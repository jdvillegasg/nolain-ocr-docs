    Asynchronous Task Processing

    This document explains how the system handles long-running tasks using Celery and Redis.

    Overview

    Asynchronous task processing allows the system to: - Handle time-consuming operations without blocking HTTP requests - Process multiple documents in parallel - Provide real-time progress updates to users - Retry failed tasks automatically

    Architecture

    Components

    Celery: Distributed task queue - Picks up tasks from Redis - Executes background jobs - Reports progress and results

    Redis: Message broker and result backend - Stores task queue - Stores task results (temporary) - Pub/Sub for real-time updates

    FastAPI Backend: Task producer - Queues tasks via Celery - Subscribes to progress updates - Streams updates to frontend via SSE

    Task Flow

    sequenceDiagram
    participant Frontend
    participant Backend
    participant Redis
    participant Celery

    Frontend->>Backend: POST /extract_multiple_images
    Backend->>Redis: Queue task
    Backend-->>Frontend: task_id

    Frontend->>Backend: GET /stream/{task_id} (SSE)
    Backend->>Redis: Subscribe to channel

    Celery->>Redis: Get task
    Celery->>Redis: Publish "processing"
    Redis-->>Backend: Event
    Backend-->>Frontend: SSE: processing

    loop Process images
        Celery->>Redis: Publish progress%
        Redis-->>Backend: Event
        Backend-->>Frontend: SSE: progress
    end

    Celery->>Redis: Publish "completed"
    Redis-->>Backend: Event
    Backend-->>Frontend: SSE: completed + results

    Celery Configuration

    Setup (core/celery_app.py)

    from celery import Celery

celery_app = Celery(
    "nolain_ocr",
    broker=settings.CELERY_BROKER_URL,      # redis://redis:6379/0
    backend=settings.CELERY_RESULT_BACKEND  # redis://redis:6379/0
)

celery_app.conf.update(
    task_serializer='json',
    accept_content=['json'],
    result_serializer='json',
    timezone='UTC',
    enable_utc=True,
)

celery_app.autodiscover_tasks(['backend.tasks'])

    Running Worker

    Docker:

    celery -A backend.core.celery_app.celery_app worker --loglevel=info

    Local:

    cd /path/to/project

    Task Definition

    Extraction Task (tasks/extraction.py)

    @celery_app.task(bind=True)
def process_extraction_task(
    self,
    folder_id: str,
    user_id: str,
    template_group: list | None = None
):
    task_id = self.request.id

    # Publish initial status
    redis_client.publish(f"task_updates:{task_id}", json.dumps({
        "status": "processing",
        "progress": 0
    }))

    try:
        # Load images
        images = load_images_from_folder(folder_id)

        # Group by template if specified
        if template_group:
            image_groups = group_images(images, template_group)
        else:
            image_groups = [[img] for img in images]

        # Process each group
        results = []
        for i, group in enumerate(image_groups):
            # Extract
            if len(group) > 1:
                combined = combine_images(group)
                result = extract_text_from_image(combined, user_id)
            else:
                result = extract_text_from_image(group[0], user_id)

            results.append(result)

            # Publish progress
            progress = int((i + 1) / len(image_groups) * 100)
            redis_client.publish(f"task_updates:{task_id}", json.dumps({
                "status": "processing",
                "progress": progress
            }))

        # Bill processed pages
        bill_processed_pages(user_id, len(image_groups))

        # Publish completion
        redis_client.publish(f"task_updates:{task_id}", json.dumps({
            "status": "completed",
            "progress": 100,
            "results": results
        }))

        return {"status": "completed", "results": results}

    except Exception as e:
        # Publish failure
        redis_client.publish(f"task_updates:{task_id}", json.dumps({
            "status": "failed",
            "error": str(e)
        }))
        raise

    Real-time Progress Updates

    Redis Pub/Sub

    Channel Naming: task_updates:{task_id}

    Message Format:

    {
  "status": "processing",  // "processing", "completed", "failed"
  "progress": 45,          // 0-100
  "results": {...},        // Only on completion
  "error": "..."           // Only on failure
}

    SSE Endpoint (api/api_v1/endpoints/sse.py)

    @router.get("/stream/{task_id}")
async def task_updates_stream(task_id: str):
    async def event_generator():
        pubsub = redis_client.pubsub()
        pubsub.subscribe(f"task_updates:{task_id}")

        try:
            for message in pubsub.listen():
                if message['type'] == 'message':
                    data = message['data'].decode('utf-8')
                    yield f"data: {data}\n\n"

                    # Close on completion or failure
                    parsed = json.parse(data)
                    if parsed['status'] in ['completed', 'failed']:
                        break
        finally:
            pubsub.unsubscribe()
            pubsub.close()

    return EventSourceResponse(event_generator())

    Frontend SSE Client

    const eventSource = new EventSource(`/api/stream/${taskId}`)

eventSource.onmessage = (event) => {
  const data = JSON.parse(event.data)

  if (data.status === 'processing') {
    updateProgressBar(data.progress)
  } else if (data.status === 'completed') {
    displayResults(data.results)
    eventSource.close()
  } else if (data.status === 'failed') {
    showError(data.error)
    eventSource.close()
  }
}

    Task Monitoring

    Checking Task Status

    from celery.result import AsyncResult

task = AsyncResult(task_id)
print(task.state)  # PENDING, STARTED, SUCCESS, FAILURE
print(task.info)   # Task return value or exception

    Task States

    • PENDING: Task queued, not yet started
    • STARTED: Worker picked up task
    • SUCCESS: Task completed successfully
    • FAILURE: Task failed with exception
    • RETRY: Task being retried
    • REVOKED: Task cancelled

    Error Propagation

    Task Failure: 1. Exception caught in task 2. Error published to Redis 3. Frontend receives via SSE 4. User notified with error message

    Partial Failures: - Continue processing remaining items - Report which items failed - Return partial results

    Performance Considerations

    Concurrency

    Single Worker: - Processes one task at a time - Other tasks queued in Redis

    Multiple Workers:

    celery -A backend.core.celery_app.celery_app worker --concurrency=4

    Task Prioritization

    # High priority
extraction_task.apply_async(args=[...], priority=9)

# Low priority
extraction_task.apply_async(args=[...], priority=1)

    Memory Management

    Large Datasets: - Process in chunks - Stream results instead of loading all at once - Clean up temporary files after processing

    Use Cases

    Use Case 1: Batch Document Extraction

    Scenario: User uploads 100 PDF pages

    Process: 1. Upload completes → returns folder_id 2. User clicks "Extract All" 3. Backend queues Celery task 4. Returns task_id immediately 5. User sees progress bar 6. Task processes images in parallel 7. Results saved to database 8. User notified when complete

    Benefits: - No request timeout - User doesn't wait - Can navigate away and return

    Use Case 2: Template Processing

    Scenario: Extract 50 invoices with 2 pages each

    Configuration:

    {
  "template_group": [
    ["invoice1_page1.jpg", "invoice1_page2.jpg"],
    ["invoice2_page1.jpg", "invoice2_page2.jpg"],
    // ... 48 more
  ]
}

    Process: 1. Task combines each pair of pages 2. Processes 50 combined images 3. Updates progress after each invoice 4. Returns 50 extraction results

    Troubleshooting

    Task Not Processing

    Symptoms: Task stays in PENDING state

    Causes: - Celery worker not running - Redis connection issues - Task not registered

    Solutions:

    # Check worker status
celery -A backend.core.celery_app.celery_app inspect active

# Check Redis connection
redis-cli ping

# Restart worker
docker-compose restart celery_worker

    Worker Crashes

    Symptoms: Worker disconnects, tasks fail

    Causes: - Out of memory - Unhandled exceptions - Resource exhaustion

    Solutions: - Monitor worker logs: docker-compose logs -f celery_worker - Increase memory limit in docker-compose - Add error handling to tasks

    Progress Not Updating

    Symptoms: Frontend shows 0% indefinitely

    Causes: - SSE connection closed - Redis pub/sub not working - Task not publishing updates

    Solutions: - Check browser console for SSE errors - Verify Redis pub/sub: redis-cli PSUBSCRIBE 'task_updates:*' - Check worker logs for task execution
