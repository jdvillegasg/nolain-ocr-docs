    Stripe Integration & Billing

    Overview

    The Nolain OCR application uses Stripe for two billing models:

    1. Recurring subscriptions — Pro ($9/mo) and Pro Plus ($29/mo) plans with monthly page quotas
    2. One-time top-up packs — Page credits ($2 / $5 / $10 / $15) that overflow monthly quota

    Both can coexist: monthly plan quota is consumed first, then top-up credits.

    Architecture

    Frontend (AccountPage, LandingPage)
    ↓
Backend (payment_service.py, page_billing_service.py)
    ↓
Stripe (Checkout, Customer Portal, Webhooks)
    ↓
Supabase (subscriptions, topup_credit_purchases tables)

    Subscription Lifecycle

    1. Checkout: User selects a plan → POST /create-checkout-session → Stripe Checkout
    2. Webhook: checkout.session.completed → backend creates/updates subscriptions record
    3. Usage: Pages billed after extraction via page_billing_service
    4. Renewal: invoice.payment_succeeded resets total_pages_processed counter
    5. Management: Users access Stripe Customer Portal via POST /create-billing-portal-session
    6. Plan changes: POST /update-subscription for upgrades (immediate) or downgrades (at period end)
    7. Cancellation: POST /cancel-subscription schedules cancellation at period end

    Top-up Pack Lifecycle

    1. Browse: GET /topup-packs returns available packs and per-page rates
    2. Checkout: POST /create-topup-checkout → Stripe one-time payment
    3. Webhook: checkout.session.completed → credit topup_page_credits in subscriptions
    4. Confirm: POST /confirm-topup-checkout for idempotent credit confirmation
    5. Usage: Top-up credits consumed only after monthly plan quota is exhausted

    Top-up Pack Tiers

    Pack Default Price Per-Page Rate
    Small $2 $0.35/page
    Medium $5 $0.30/page
    Large $10 $0.20/page
    XL $15 $0.15/page

    Configured via STRIPE_API_TOPUP_{2,5,10,15}_PRICE_ID and API_TOPUP_* env vars. Packs without a Stripe Price ID are hidden from the catalog.

    Page Billing Priority

    1. Monthly plan quota (free tier or active subscription)
2. Top-up page credits (overflow)
3. 402 Payment Required if both exhausted

    Admin users (ADMIN_USER_ID) bypass all limits.

    Database Schema

    subscriptions table

    Column Purpose
    user_id Supabase auth UUID
    plan_tier free, pro, pro_plus
    status free, active, canceled, past_due
    stripe_customer_id Stripe customer
    stripe_subscription_id Active subscription
    topup_page_credits Overflow page balance
    total_pages_processed Monthly usage counter
    current_period_start/end Billing period
    cancel_at_period_end Scheduled cancellation flag

    topup_credit_purchases table

    Idempotent record of completed top-up checkouts (stripe_session_id unique).

    Security Best Practices

    1. Secret Keys: Never expose STRIPE_SECRET_KEY or STRIPE_WEBHOOK_SECRET on the frontend
    2. Webhook Verification: Backend verifies signature on every webhook event
    3. HTTPS: Required for production webhook endpoints
    4. Service Role Key: SUPABASE_SERVICE_ROLE_KEY required for webhook writes under RLS

    Local Development

    Forward Stripe webhooks to the local backend:

    stripe listen --forward-to localhost/webhook

    Copy the webhook signing secret to STRIPE_WEBHOOK_SECRET in .env.

    For API calls through Docker nginx, use localhost/webhook (not /api/webhook).

    Troubleshooting

    Webhook Issues

    • Verify STRIPE_WEBHOOK_SECRET matches the Stripe Dashboard (or stripe listen output)
    • Check the Events tab in Stripe Dashboard for delivery logs
    • Ensure the server is accessible from the internet (production)

    Subscription Sync Issues

    • Check backend logs for webhook processing errors
    • Verify user_id in metadata matches the database record
    • Ensure SUPABASE_SERVICE_ROLE_KEY is set for RLS bypass

    Top-up Credits Not Applied

    • Check topup_credit_purchases for duplicate stripe_session_id
    • Verify STRIPE_API_TOPUP_*_PRICE_ID env vars are set
    • Call POST /confirm-topup-checkout after redirect
